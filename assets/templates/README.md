# Writing prompts

Three shapes, depending on what you're documenting.

- **[Strategy](strategy.md)** — one behavior, funded and running. Start with what it does for the reader.
- **[Use case](use-case.md)** — a person or project in a situation. Start with the situation.
- **[System](system.md)** — several strategies as one treasury. Start with what the whole thing is for.

These are prompts, not required headings. Use whatever structure carries the idea.

## What every page needs

**Outcome before mechanism.** The reader should know why they'd want this before they learn how it works.

**Real numbers.** Actual assets, actual amounts. Percentages and "units" make readers do work they shouldn't have to.

**A separate section on what to watch for.** Honest failure modes, collected at the end rather than scattered where they undercut the explanation.

**No hedging.** Drop "supported", "eligible", "compatible". If something works, say so plainly; if it has a limit, name it.
